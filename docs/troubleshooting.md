# 故障排查

## 1. 选择了绿色版 / 便携版，仍提示路径无效

1. 优先选择**客户端根目录**（其中应包含 `resources\app`）或直接把 `GitHubDesktop.exe` / 客户端文件夹拖进窗口；也可直接粘贴 `resources\app` 的完整路径。
2. 工具会从 `package.json` 或 `app-X.Y.Z` 目录读取版本。若便携版被精简到没有 `package.json`、目录名也不含版本号，会要求你二次确认后才能强制应用。
3. 如果客户端只有 `resources\app.asar`，说明程序被单包封装，本工具**不支持直接改写 ASAR**。请改用官方安装包或解包版客户端。强行改名/解包可能让客户端无法启动。

## 2. 提示“客户端版本与所选汉化版本不一致”

这是保护机制：把不匹配的 `main.js` / `renderer.js` 写入客户端，可能导致客户端打不开。

- 在「帮助 → 关于 GitHub Desktop」确认客户端版本。
- 若版本未内置（例如官方最新 3.7.0），到「字典」页点击**导入汉化包…**，选择下载好的版本文件夹，工具会自动放入本地字典。
- 高级用户可用 `cli.py apply --allow-mismatch` 显式绕过，但风险自负。

## 3. 下载了汉化文件，不想手工建 `dictionaries/<版本>/`

使用「字典」页的**导入汉化包…**：

- 可选择包含 `main.js` + `renderer.js` 的文件夹、其上级目录，或上游的 `Windows` 目录。
- 工具会从文件夹名 / `provenance.json` 推断版本；无法推断时提示输入。
- 导入后立即刷新版本列表并自动选中，**无需重启**。

安全提示：导入的 JavaScript 会被 GitHub Desktop 执行，只使用可信来源。本地字典会在列表中标记「（本地）」，不能通过内置散列校验。

## 4. 汉化完成但界面还是英文

- 完全退出 GitHub Desktop 再重新打开。
- 确认选择的版本与客户端完全一致。
- 若使用 3.6.10，部分未匹配文案可能保留英文，这是上游译文覆盖度限制。

## 5. 想恢复英文原版

首页「还原为英文原版」会从 `.bak` 事务式还原两个文件。还原要求两个备份都存在；缺失一个时会拒绝执行，避免留下半中文半英文状态。

## 6. “禁止自动更新”的行为

- 开关**只反映当前实际状态**，启动或刷新时不会自动修改 `Update.exe`。
- 只有你点击开关时才会改名为 `Update.exe.disabled`。
- 这会同时阻断 GitHub Desktop 的**安全更新**；建议只在确认需要锁定版本时使用，并定期手动更新后重新应用汉化。
- 绿色版通常没有 `Update.exe`，因此开关会显示“无更新器”且不可操作，工具不会去改其他安装。

## 7. 运行日志与诊断

- 日志目录：`%LOCALAPPDATA%\GitHubDesktopZh\logs\app.log`（滚动保留）。
- 发生未捕获异常时会弹窗并给出日志路径。
- 反馈问题时请提供：客户端版本、汉化版本、操作步骤、日志尾部内容；**不要**附加含个人信息的路径或仓库内容。

## 8. 外观：明暗主题

- **主题始终跟随 Windows**，没有手动切换按钮。切换系统「应用模式」后界面会自动更新；若未更新，重新打开工具即可。
- 界面使用**中性实体表面**；点击、拖动、窗口切换都不会换色。
- 高对比度模式下交还系统调色板，保证文字可读性。
- 无边框标题栏负责拖动，边缘负责缩放。
- EXE 只内置最新 2 版字典（3.6.10、3.6.7），其他版本在「字典」页导入。

## 9. 构建与测试

```bat
cd gui
build.bat
```

构建会：校验 Python 3.10–3.13 → 安装锁定依赖 → 校验字典清单与 JS 语法 → 隐私/self/一致性/对比度/截图门禁 → 打包 → 校验归档 → 生成 `SHA256SUMS.txt` / `build-info.json`（本地验证产物）。

开发测试：

```bash
python -m unittest discover -s tests -v
```

AST 校验器需要 Node.js 与 `.work/js-parser` 下的 Acorn 8.15.0；CI 中通过 `GDF_REQUIRE_NODE=1` 禁止静默跳过。
